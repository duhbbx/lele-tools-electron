# 踩坑与要点

## monorepo 骨架

- `pnpm-workspace.yaml` 声明 `apps/*` 和 `packages/*`，根 `package.json` 只装 devDeps（biome、typescript、vitest）。
- 拷贝 db-tool 的 `vitest.config.ts` 需删头部公司版权注释；`tsconfig.base.json` 和 `biome.json` 无需改动。
- `pnpm.onlyBuiltDependencies` 需列 `electron`、`esbuild`、`better-sqlite3`，否则 pnpm v10 不执行其 postinstall 脚本。
- biome 安装后 pnpm 会提示 "Ignored build scripts"，运行 `pnpm approve-builds` 可解决（或在 `onlyBuiltDependencies` 里加 `@biomejs/biome`）。

## ui 包外壳（i18n / 样式 / registry）

- db-tool 的 `packages/ui/src/env.d.ts` 无 `Window.api` 声明，按计划写新版（`vite/client` reference + `Window.api: WindowApi`）。
- `tsconfig.json` 从 db-tool 直接复制无需改动（无 `@db-tool` 路径引用，`extends ../../tsconfig.base.json` 路径一致）。
- `vue-tsc --noEmit` typecheck 零报错；`styles.scss` 不被 TS 检查，只做静态资源导出，不影响 typecheck。

## pnpm workspace TS 源码包模式

- **`@lele/ui` 和 `@lele/shared-types` 均以 TS 源码直接消费**：`package.json` 的 `exports` 字段指向 `./src/index.ts`，消费方（apps/desktop）零构建步骤。
- Vite 侧须把这两个包加入 `optimizeDeps.exclude`，让它们走源码路径而非预构建缓存；TypeScript 侧须在 `tsconfig` 的 `paths` 或 `references` 中指向源码入口（确保 vue-tsc 能解析类型）。
- 包无 `dist/`，所以不能用 `pnpm build` 预发布，也不能在 `pnpm pack` 产物中依赖它们——打包时 electron-vite 会直接把源码 bundle 进去。

## shared-types 包（IPC 契约）

- 以 TS source 直接导出（`exports` 指向 `./src/index.ts`），消费方零构建步骤；仅 `typecheck` script（`tsc --noEmit`）不产出 dist。
- `tsconfig.json` 从 db-tool 直接复制可用，`extends: ../../tsconfig.base.json` 在本 monorepo 路径一致，无需改动。
- `noUnusedLocals` / `noUnusedParameters` 继承自 `tsconfig.base.json`，纯接口文件无变量故 typecheck 零报错。

## desktop 应用启动（electron-vite）

- `better-sqlite3` 原生模块编译需 `PYTHON=python3.9 pnpm install`（系统默认 python 3.14 缺 distutils）。
- `--no-expose-wasm` flag 在 Node 24 下被 Electron 34 报错，属已知兼容问题，窗口仍可正常启动，非阻断性。
- renderer dev server 端口 5173/5174 被占时 electron-vite 自动递增（可在日志中看到实际端口）。
- tsconfig.node.json 加 `"types": ["node", "electron-vite/node"]`；tsconfig.web.json 加 `"types": []`（避免 node types 污染渲染层）。
- `optimizeDeps.exclude: ['@lele/ui', 'monaco-editor']` 让 ui 源码包和 monaco 走 Vite 非预构建路径，是 TS 源码包直消费的关键。

## sqlite store + preload 桥（Task 5）

- db-tool 的 `sqlite.ts` 使用 `SCHEMA_SQL` 常量 + 内部 `migrate()` 做列补丁；lele 版直接用 `schema.ts` 导出的 `migrate(db)` 函数，无需 `SCHEMA_SQL` 中间层，sqlite.ts 更简洁。
- `better-sqlite3` 需在 `pnpm install` 后单独 `rebuild:native`（`electron-builder install-app-deps`），否则 NODE_MODULE_VERSION 不匹配 Electron 内置 Node 版本。
- preload 类型标注用 `Pick<WindowApi, 'store' | 'recents' | 'chats'>`，Task 9 加 ai 桥后再改为 `WindowApi`。
- `closeDb()` 挂在 `window-all-closed` 事件，macOS 上关最后一窗也会触发，适合统一 cleanup。

## 渲染层 settings.ts（双层持久化）+ 主题（Task 6）

- `settings` 用 `reactive<Settings>(load())`，`load()` 同步读 localStorage（0ms，避免首屏闪），SQLite 是真源（`hydrateSettings` 异步拉取并 `Object.assign` 覆盖）。
- `watch(settings, ..., { deep: true })` 同时写 localStorage（缓存）和 `window.api.store.set`（SQLite），实现双层持久化。
- `matchMedia` 和 `localStorage` 都用 `typeof xxx !== 'undefined'` 守卫，确保 ui 包在 SSR/Node 环境 typecheck 不报错。
- `applyTheme()` 写 `document.documentElement.dataset.theme`，配合 `styles.scss` 的 `:root[data-theme='dark'/'light']` 选择器实现即时主题切换。
- `initSettings()` 在 main.ts 的 `createApp().mount()` 之前调用，保证主题/locale 在首帧已生效。
- `aiProviders` 字段名是 ai.ts (Task 9) 的 load-bearing 约定，不得重命名。
- `hydrateSettings()` 从 SQLite 读取时必须深合并 `aiProviders`（`{ ...settings.aiProviders, ...parsed.aiProviders }`），否则浅合并会覆盖整个对象，导致新增 provider 的默认值丢失。

## AI 主进程 IPC 代理（绕 CORS）

- **AI 请求必须走主进程 fetch**：渲染层直接调用 OpenAI/Claude 等 API 会被 Electron 的 CORS 策略拦截；主进程无 CORS 限制，通过 `ipcMain.handle('ai:stream', ...)` 接收请求后用 Node `fetch` 转发，再把 SSE 分块 `ipcRenderer.emit('ai:stream:<reqId>', chunk)` 推回渲染层。
- preload 的 ai.stream 方法在 `ipcRenderer.invoke('ai:stream', req)` 前注册 `ai:stream:<reqId>` channel 监听，`.finally()` 里移除——这样无论成功/失败/abort 都不泄露监听器。
- 对话历史通过 better-sqlite3 存本地 SQLite，`chats` 表 + `chat_messages` 表；preload 桥暴露 `chats.*` CRUD 方法给渲染层。

## AI 三层搬运（Task 9）

- 主进程 ipc/ai.ts 零外部依赖，直接拷贝删头即可；`AiFetchRequest/Response` 在文件内自带，无需引 shared-types。
- `packages/ui/src/ai.ts` 从 db-tool 搬运后需删除 `fmtOracleType`、`AiMode`、`AskOptions`、`askAi/askClaude`、`extractAllSql/extractSql`、`embedTexts`、`isLocalEmbeddingBase`、`canEmbed` 及其 `DbDialect` import；保留 SSE pipeline（`aiBridge/aiHttp/aiHttpStream`）、`askAiChat/askAiChatStream`、`testAiProvider`。
- vitest 在 node 环境跑 ai.test.ts 时，settings 的 Vue watcher 触发后调用 `window.api` 会报 `ReferenceError: window is not defined`（unhandled rejection），但测试本身全部通过；属 node/jsdom 环境副作用，非阻断问题。
- 修复：`hydrateSettings`、watch 回调里的 `window.api`、以及 `applyTheme` 里的 `document` 都用 `typeof xxx !== 'undefined'` 守卫，彻底消除 node 环境下的 unhandled rejection。
- `packages/ui/package.json` 的 test script 不能直接 `vitest run`（本地无 vitest.config，找不到 include globs）；改为 `pnpm -w run test packages/ui`，借用根配置并传 pattern 筛选。

## Monaco NLS 中文 + 编辑器组件（Task 11）

- **Monaco NLS shim 必须用 `resolveId` Vite 插件**（不能用 `resolve.alias`）：`resolve.alias` 截不到 monaco 内部的相对 `nls.js` 引用；`resolveId` 插件可同时匹配外部 import 和 monaco 内部相对路径，将两者统一重定向到 `monaco-nls-shim.ts`。**同时** monaco-editor 须加入 `optimizeDeps.exclude`，否则预构建时 shim 无效。
- `packages/ui` 不依赖 vite，`env.d.ts` 有顶层 `import`（变成 module 文件），其中的 `declare module '*?worker'` 失效。解决：新建纯 ambient 文件 `vite-assets.d.ts`（无 import，只有 `declare module`），专门放 `?worker`/`?url`/`?raw` 声明。
- `monaco-setup.ts` 从 db-tool 搬运时，删掉 SQL 补全 provider 及相关类型/Map（`Suggestion`、`CompletionSource`、`sources`、`setCompletionSource`、`clearCompletionSource`、`KIND_MAP`、`registerCompletionItemProvider`），只保留 `import './monaco-nls'`、`self.MonacoEnvironment` worker 配置和 `export { monaco }`。无 `setupMonaco` 导出，MonacoEditor.vue 改用 `import '../monaco-setup'` 副作用形式。
- `monaco-nls.ts` 中 `localStorage.getItem('skylerx.locale')` → `'lele.locale'`；全局标记 `_SKYLERX_NLS_DISABLED` → `_LELE_NLS_DISABLED`；同步改 `monaco-nls-shim.ts`。
- `mongo-nls-shim.ts` 的 debug `_dlog`/`console.warn` 可裁减；关键是保留数字 idx 路径（`lookupByIndex`）和字符串 fallback 路径（`lookupByFallback`）两条查表链。

## JSON / XML / YAML 格式化工具（Task 12）

- `xml-format.ts` 用浏览器 `DOMParser` 校验，vitest 默认 node 环境没有 `DOMParser`；测试文件顶部加 `/** @vitest-environment jsdom */` docblock，根 `package.json` devDeps 加 `"jsdom": "^25.0.0"` 再 pnpm install。
- `[monacoNlsShim] redirected` 日志只在 Monaco 模块实际被 Vite 解析时打印（懒加载 Tool.vue 触发 monaco import）；`pnpm dev` 冷启动时不会出现，需要用户打开一个格式化工具才触发。
- yaml-formatter 的 `lang` ref 类型标注为 `ref<'yaml' | 'json'>` 才能让 MonacoEditor `:language` prop 通过 vue-tsc 类型检查，直接 `ref('yaml')` 会推断为 `string` 而报错。

## AiChatPanel + SettingsDialog AI 区（Task 10）

- `AiTestResult` 实际字段：`{ ok: boolean; message: string; latencyMs?: number; modelCount?: number }`；`runTest()` 用 `r.ok ? \`OK: ...\` : r.message` 完全对齐，无需适配。
- `marked.parse(md, { async: false }) as string` 适用于 marked v18；返回类型在 async:false 时实际为 string，类型系统需要显式断言。
- Workspace.vue 中 `locale` 从 i18n 引入但 `toolContext` computed 不需要它（直接写死 `.en/.zh` 字段名），删去该 import 保持 typecheck 干净。
- SettingsDialog 的 AI 区脚本全部写在同一个 `<script setup>` 块里（不是单独 `<script>`），追加 import 时注意 `ref` 已可能被其他 import 覆盖，合并到同一 `import { ref } from 'vue'` 行。

## Base64 / 进制转换工具（Task 13）

- `btoa`/`atob` 在 Node ≥16 全局可用，base64 的 codec.test.ts 无需 jsdom；`TextEncoder`/`TextDecoder` 同理。
- `decodeB64` 用 `TextDecoder('utf-8', { fatal: true })` 确保遇到非法 UTF-8 字节时抛出，满足"invalid input throws"测试用例。
- 进制转换用 BigInt 实现（避免 `Number` 丢精度），`DIGITS` 字符串 `indexOf` 做字符→数字映射，同时自动处理大小写（`.toLowerCase()`）。
- Tool.vue 中「复制」按钮一律 `import { copyText } from '../../clipboard'`，不直接在模板里调用 `navigator.clipboard`（Vue 模板表达式访问不到浏览器全局）。

## 正则测试 / 字符统计（Task 14）

- `countText` 用 `[...s].length` 而非 `s.length` 统计字符数，正确处理 emoji 等多码元字符。
- CJK 范围：`[一-鿿㐀-䶿]`（CJK 统一汉字 + CJK 扩展 A），英文词用 `/[A-Za-z0-9_'-]+/g`，两者互不干扰。
- 正则测试工具：`g` flag 用 `matchAll`（可迭代），非 `g` 用 `exec`，均包在 try/catch 里展示错误；`matchAll` 上限 500 防卡顿。

## 文本加解密 AES-256-GCM（Task 15）

- Node ≥20 全局提供 `crypto.subtle`（Web Crypto API），无需 import，vitest 测试直接可用。
- `crypto.getRandomValues(new Uint8Array(N))` 返回 `Uint8Array<ArrayBufferLike>`，直接传给 `crypto.subtle.deriveKey` 的 `salt` 参数时 vue-tsc 5.x 会报 `BufferSource` 不兼容（`ArrayBufferLike` 不可赋给 `ArrayBuffer`）。解决：`.buffer.slice(byteOffset, ...)` 取出纯 `ArrayBuffer` 再包成 `new Uint8Array(buf)` 传入。

## UUID / 随机密码生成（Task 16）

- `crypto.randomUUID()` 返回 TypeScript 字面量类型 `` `${string}-${string}-${string}-${string}-${string}` ``；赋值后调用 `replaceAll` 改变了结构，必须先用 `let u: string = crypto.randomUUID()` 显式放宽类型，否则 vue-tsc 报不可赋值错误。
- 密码生成：先保证每类字符至少一个，再随机填充至目标长度，最后 Fisher-Yates 洗牌；`randInt` 用 `crypto.getRandomValues(new Uint32Array(1))` 取密码学随机数，避免 `Math.random()` 偏差。
- `CLASSES` 去掉 `l/o/0/1/I/O` 等易混字符，减少密码使用中的辨识错误。

## 二维码生成（Task 17）

- `qrcode` 包已在 `packages/ui/package.json` dependencies 声明；`@types/qrcode` 在 devDependencies，无需额外安装。
- `watchEffect` 监听 `text/size/ecc` 三个 ref，canvas 挂载后自动触发；`toCanvas` 返回 Promise，错误用 `.catch` 写到 `error` ref 显示。
- 下载用 `canvas.toDataURL('image/png')` + 动态 `<a>` click，无需依赖 `canvas.captureStream` 等 API。

## 时间戳·日期 / Cron（Task 18）

- `cron-parser` v4 类型文件只导出命名函数（`parseExpression`），没有 default export；用 `import { parseExpression } from 'cron-parser'`，不要 `import parser from 'cron-parser'`（会导致 TS 报 no default export 错误）。
- `normalizeTs` 判断秒/毫秒：`Math.abs(n) < 1e12` 视为秒乘 1000，10 位秒级时间戳最大 ~9999 年（9999999999 < 1e12），13 位毫秒级最小 1000000000000 ≥ 1e12。

## 打包 electron-builder（Task 20）

- **better-sqlite3 双重要求**：开发安装时 `export PYTHON=python3.9 && pnpm install`（系统默认 python 3.14 缺 distutils，node-gyp 编译失败）；打包时 `asarUnpack: ['**/*.node']` 确保 `.node` 文件解包到 `asar-unpacked/` 目录，运行时加载不报 MODULE_NOT_FOUND。
- `pnpm --filter @lele/desktop pack` 等价于 `pnpm pack`（创建 tgz 压缩包），实际打包用 `pnpm --filter @lele/desktop run pack`（运行 package.json 的 pack script → `electron-builder --dir`）。
- electron-builder 会自动调用 `@electron/rebuild` 重新编译 `better-sqlite3`（ABI 匹配 Electron 内置 Node 版本）。
- 图标来源只有 256×256 PNG 时，用 `sips -z 1024 1024 src.png --out icon.png` 放大到 1024×1024，electron-builder 从单张 PNG 自动派生各平台所需尺寸（macOS .icns / Windows .ico）。
- `*.tgz` 应加入 `.gitignore`，避免 `pnpm pack` 的产物污染仓库（`pnpm --filter` 在 monorepo 根运行时 tgz 会生成在根目录）。

## VitePress 官网脚手架（Task W1）

- DBW `config.ts` 调用 `makeThemeConfig(ZH, '')` 传的是 `LocaleLabels` 对象；我们的 `i18n.ts` 改为 `makeThemeConfig(localeKey: string, prefix: string)` 接受字符串 key。`config.ts` 里对应改为 `makeThemeConfig('zh-CN', '')` 等；locales 字段从 `ZH/EN/...` 导出对象取 `label/lang/description` 属性来填写。
- DBW `LOCALE_META` 有 `ogTitle/ogDescription` 子字段；我们的精简版只有 `lang/label/title/description`。`makeLocaleHead` 返回 `og:locale + og:site_name` 两条标签，而不是 DBW 的 `description+og:title+og:description`。
- VitePress dev server HTML 中 `<title>` 为空是正常行为（SPA shell，标题由 Vue 运行时注入）；验证应用 build 产物：`grep -o '<title>[^<]*' .vitepress/dist/index.html`。
- `ignoreDeadLinks: true` 让 build 时其他 locale 子目录缺失也不报错，不需要在 W1 阶段创建占位 index.md。

## 颜色工具 / HTTP 状态码表（Task 19）

- `hexToRgb` 3 位短格式扩展：`[...h].map((c) => c + c).join('')`，将 `f80` → `ff8800`，再走 6 位路径。
- `rgbToHsl` 色相计算：`max === min` 时（灰色/黑/白）直接返回 h=0 s=0，避免除零；其他分支按 RGB 最大分量确定色相。
- HTTP 状态码数据用 IANA 标准 reason phrase 作 `name` 字段（如 `Content Too Large` 而非旧称 `Request Entity Too Large`），`zh` 字段一句话概述，参照 Qt 版 `httpstatuscode.cpp` 的中文描述。

## 布局滚动约束（overflow 链）

- **flex 子项必须加 `min-height: 0`（或 `min-width: 0`）才能被压缩**：flex 默认 `min-height: auto`，即使设了 `flex: 1` 也会被内容撑开、溢出到页面级滚动。
- 完整链路：`html/body/#app { overflow: hidden }` → `.workspace { height: 100% }` → `.scroll`（SideNav）加 `min-height: 0` → `.body`（Workspace）加 `overflow: hidden` → `.pane` 加 `overflow: hidden`，让 `.tool-page { overflow: auto }` 自己滚。
- AiChatPanel `.list { flex: 1; min-height: 0; overflow-y: auto }` 同理。
- **CSS Grid 行约束**：`.workspace` 用 `grid-template-columns` 但若未设 `grid-template-rows`，隐式行的 `min-height: auto` 会让行随内容撑高，超出容器后内容被 `#app overflow:hidden` 裁掉（.foot 不可见）且内部 flex 列没有高度上限（.scroll 永不滚动）。修复：加 `grid-template-rows: minmax(0, 1fr)`，把唯一行约束到容器高度。

## Electron 原生菜单 + IPC 设置入口

- `Menu.setApplicationMenu` 在 `app.whenReady` 里调用；macOS 第一项用 app name 的 submenu 放「设置…」，Win/Linux 放在「文件」submenu。
- 菜单触发 UI 操作：主进程无法直接操 Vue state，统一 `win.webContents.send('menu:open-settings')` 到渲染层；preload `ipcRenderer.on` 桥接；Workspace `onMounted` 订阅。
- `BrowserWindow.getFocusedWindow() ?? BrowserWindow.getAllWindows()[0]` 是安全的 fallback，避免 macOS 窗口失焦时 getFocusedWindow 返回 null。
- 删掉侧边栏中的触发点后，在 `defineEmits` 里也要同步删除该事件，否则 typecheck 不报错但遗留无用类型。

## 删除「最近使用」侧边栏区块

- 仅删 UI：`recents.touch` 的调用保留（sqlite 数据继续维护，供未来复用），只去掉渲染层展示。
- SideNav.vue：删 `recents` ref、`onMounted` 加载、`refreshRecents()`、`defineExpose`、模板 `<template v-if="!query && recents.length">` 块及其依赖的 `toolById` import。
- Workspace.vue：删 `navRef` ref 及 `ref="navRef"` 模板属性，将 `touch().then(() => navRef.value?.refreshRecents())` 改为 `void window.api?.recents?.touch?.(id)`。

## VitePress 组件搬运（Task W3）

- DBW 组件依赖 `getComponentLabels(lang)` 函数（来自 `../i18n`）；我们的 `i18n.ts` 默认没有，需在末尾追加 `ComponentLabels` 接口 + `COMPONENT_LABELS` 数据 + `getComponentLabels` 函数。
- `sips -s format ico` 在 macOS Sequoia 可直接生成 `.ico`（以往版本不支持），可用于 favicon；config.ts `head` 已指向 `/logo.png`（PNG），两者共存无需改配置，浏览器会自动找 `favicon.ico`。
- `downloadSource.ts` 无 OSS 镜像时：`fetchFromOss` 直接 throw，`fetchLatest` 两层 try-catch 保证双源都失败时返回 `{ tag_name: null, assets: [] }` 空态；`fetchFromGithub` 空列表也返回空态而不 throw，DownloadMatrix `v-else` 分支即显示 fallback 链接，无需额外空态 UI。
- DownloadMatrix 里 OSS 相关的硬编码 URL 需同步改掉（`releasesPage`/`latestPage` computed），否则 OSS toggle 按钮会指向错误链接。

## Issue 搬运工具（issue-mover）

- **gh CLI token 不进渲染层**：主进程 `execFile('gh', ['auth','token'])` 取 token，lazy 缓存；渲染层只通过 IPC bridge (`github:fetch-issue` / `github:list-repos` / `github:create-issue`) 通信，token 始终留在主进程。
- **fetchIssue 永不 reject**：`ipcMain.handle` 内部 catch 后返回带 `error` 字段的对象，确保渲染层 UI 可统一显示错误而不 unhandled rejection。
- **PR 与 Issue 同 URL 空间**：GitHub API 返回 `pull_request` 字段存在即是 PR，需单独判断并返回 error 字段。

## 双 ABI：测试用 better-sqlite3-node，应用用 Electron 重编译版
